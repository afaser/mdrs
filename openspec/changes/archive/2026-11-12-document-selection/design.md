## Context

См. `proposal.md` — Why и `specs/{text-selection,markdown-viewer,configuration}` — требования.

Сейчас выделение живёт внутри одного виджета: `SelectableText` держит cosmic-text buffer, `InlineFlow` — логические байты блока, а `Selection`/`InlineState` хранят якорь и фокус локально. `TextState::reset_interaction` очищает выделение при любом изменении набора spans, поэтому кросс-блочный диапазон негде хранить. `ViewerText::selectable_from`/`flow_text` создают виджеты без сведений об исходном markdown, а `markdown::Text` в вендоренном `iced_widget` не хранит диапазоны источника, хотя парсер уже идёт через `into_offset_iter()`.

`view()` строит `markdown::view_with` внутри `scrollable`; `scrollable` передаёт дочерним виджетам курсор, уже сдвинутый на позицию прокрутки, но layout остаётся в координатах контента. Это позволяет держать геометрию блоков в координатах контента, а оверлей прокрутки — в координатах окна.

## Goals / Non-Goals

**Goals:**

- Один диапазон выделения на документ, переживающий ресайз и перестройку переносов.
- Два режима: построчный из левого поля и символьный внутри текста; режим фиксируется точкой нажатия.
- Копирование ровно тех строк исходного markdown, которых касается диапазон, без потери разметки и пустых строк.
- Единая геометрия подсветки: `radius`, `height`, `code-height`; цвет из палитры.
- Курсор I-beam только над выделяемой областью; arrow в промежутках; pointer на ссылках.
- Минимальная правка вендоренного iced: только диапазоны источника в markdown-модели.

**Non-Goals:**

- Автопрокрутка при протяжке за пределы окна.
- Выделение внутри изображений, горизонтальных линий и декоративных элементов.
- Попадание в буфер видимого текста вместо исходного markdown.
- Переписывание markdown-парсера или замена iced-виджетов markdown своими.
- Поддержка выделения в окне выбора файла и экранах ошибок.
- Изменение поведения Ctrl+O, live reload, скроллбаров и колеса.

## Decisions

### 1. Документная позиция вместо локального диапазона

Вводится `DocumentSelection` — состояние на документ, разделяемое всеми текстовыми виджетами через `Rc<RefCell<...>>`. Диапазон хранится как:

- `TextPosition { block: SourceStart, byte: usize }` — блок и логический байт внутри него;
- `LinePosition { line: usize }` — индекс исходной строки для построчного режима.

`SourceStart` — байтовое смещение начала markdown-элемента в исходнике; оно уникально для текстового блока и даёт порядок документа без отдельного счётчика. Сравнение позиций: сначала `SourceStart`, затем `byte`. Для построчного режима порядок задаёт индекс строки.

Виджеты больше не владеют выделением. Их локальные `TextState`/`InlineState` оставляют только hit-testing и геометрию; якорь, фокус, drag и generation переезжают в `DocumentSelection`.

Альтернативы:

- Глобальные индексы блоков, назначаемые при построении view, — ломаются на вложенных списках/таблицах и при ленивом построении строк.
- Хранить выделение в `Program` и передавать в виджеты только на чтение — drag должен менять состояние из виджета; `Rc<RefCell<_>>` проще и не требует сообщений на каждое движение мыши.

### 2. Карта источника через вендоренный markdown

`vendor/iced_widget/src/markdown.rs` уже использует `Parser::into_offset_iter()`, но выбрасывает `source: Range<usize>`. Добавляем:

- `Text { source: Range<usize>, spans: Vec<Span>, ... }` и `Text::source()`;
- `Span::Standard/Highlight { source: Range<usize>, ... }` и `Text::source_segments()` — пары «логический диапазон → диапазон источника»;
- источник для code-line `Text` из диапазона соответствующего `Event::Text` внутри `CodeBlock`; если событие содержит несколько строк, диапазон режется по переводам строк, чтобы каждая code-line получила свою исходную строку;
- `Item::CodeBlock` сохраняет диапазон содержимого без ограждения; для строк кода источник берётся из `lines[i].source()`.

`source_segments()` вычисляется по видимым spans: смещения накапливаются в порядке spans, поэтому после стилизации (разбиение на script-runs, inline-code, ссылки) логические байты не меняются — стилизация не добавляет и не удаляет символы. Это позволяет передать карту в виджет отдельно от `Arc<[Span]>`.

Новый `SourceIndex` в `src/markdown/source_index.rs` строится из исходного текста один раз на документ: список строк с байтовыми границами, `line_of(byte)`, `range(start_line, end_line)`, `line_count`. `SourceIndex` — контейнер с приватным `Vec<SourceLine>` и методами; границы нормализуются, пустой хвост после последнего перевода строки не создаёт фантомную строку.

`BlockSource` в `src/selection/block_source.rs` соединяет `Text::source_segments()` с `SourceIndex` и умеет:

- `source_at(logical_byte) -> usize`;
- `line_at(logical_byte) -> usize`;
- `lines_in(logical_range) -> Range<usize>`.

Для code-блока `BlockSource` собирается из `lines[i].source()`; логические границы строк кода совпадают с конкатенацией `code.lines()`.

Альтернативы:

- Отдельный парсер с нуля — дублирует iced markdown и рискует разойтись с рендером.
- Эвристический поиск текста блока в исходнике — ломается на разметке, экранировании и повторяющихся абзацах.

### 3. Реестр геометрии документа

Новый `DocumentGeometry` (`src/selection/document_geometry.rs`) — общий реестр, который каждый текстовый виджет обновляет в `layout()`:

- `BlockGeometry { block: SourceStart, code: bool, lines: Vec<VisualLine>, source: BlockSource }`;
- `VisualLine { bounds: Rectangle, logical: Range<usize>, source: Range<usize>, glyphs: Vec<Glyph> }` в координатах контента (не окна);
- `Glyph { x: f32, width: f32, start: usize, end: usize }` для hit-testing по x.

`SelectableText` берёт visual lines из `cosmic_text` layout runs; абсолютный логический байт строки считается как сумма длин предыдущих `BufferLine::text()` плюс `glyph.start/end`. `InlineFlow` берёт готовые `Line`/`LineItem`, где логические диапазоны уже есть.

Реестр очищается по generation документа: `Program` увеличивает generation при открытии/перезагрузке, а записи со старым generation игнорируются. Ресайз не очищает реестр — виджеты перезаписывают свои записи в новом layout. Прокрутка реестр не трогает: координаты контента не меняются, а `scrollable` сдвигает курсор и рендер.

Почему не глобальный оверлей для рисования:

- Оверлей поверх контента закрыл бы глифы, а оверлей под контентом был бы перекрыт фоном inline-чипа. Существующий порядок «фон чипа → выделение → текст» достигается только внутри виджета.
- Поэтому каждый виджет сам рисует свою часть общего диапазона, а реестр нужен только для межинтервального hit-testing и курсора.

### 4. Режимы выделения и левое поле

Режим фиксируется нажатием:

- нажатие в тексте блока — `Text`-режим; якорь берётся из локального `Paragraph::hit`/`InlineLayout::hit`;
- нажатие левее текста — `Line`-режим; якорь — исходная строка, найденная по y.

Левым полем считается область от левого края окна до `line.left` текущей строки, включая `window.padding` и отступы списков/цитат/таблиц. Это даёт выделение «с левого края» без изменения ширины контента: текст не сдвигается, а окно-паддинг становится зоной построчного выбора.

Новый прозрачный виджет `SelectionSurface` (`src/selection/selection_surface.rs`) лежит верхним слоем `stack![container(document)…, surface]`:

- в `update` перехватывает нажатие только если точка попадает в левое поле строки; иначе событие уходит контенту;
- при активном построчном drag сам ведёт диапазон и перехватывает движения/отпускание;
- в `mouse_interaction` возвращает I-beam только над левым полем, иначе `None`, чтобы `stack` отдал решение виджету текста или обычной стрелке;
- не рисует ничего.

Координаты: `SelectionSurface` получает позицию прокрутки из `Program` и переводит окно → контент как `point - scrollable_origin + offset`. `scrollable_origin` = позиция surface + `window.padding`. Виджеты внутри `scrollable` получают уже сдвинутый курсор, поэтому их межинтервальный hit-testing работает в тех же координатах контента.

Альтернативы:

- Сделать каждый блок full-width и искать gutter внутри него — ломает shrink-раскладку таблиц и выравнивание.
- Добавить отдельную колонку-gutter — сдвигает весь документ и меняет вид без запроса.

### 5. Отрисовка подсветки

`DocumentSelection` отдаёт виджету пересечение общего диапазона с его блоком:

- `Text`-режим — существующие `Selection::bounds`/`InlineLayout::selection_bounds` для локального диапазона; прямоугольники скругляются `theme.selection.radius`;
- `Line`-режим — по одной строке на каждый visual line, чей `source` пересекает выбранные строки; ширина — от левого края контента до правого края `surface`; высота — `headings.hN` для заголовка уровня N, `code-height` для строк fenced-блока, содержащего больше одной строки кода, иначе `height`; центр — по центру visual line.

Подсветка рисуется после фона inline-чипа и до глифов, как сейчас. Цвет — `theme.selection.color`, резолвится через палитру. Радиус применяется к каждому прямоугольнику, а не к объединённой области: соседние visual lines остаются раздельными, как в редакторах.

Пустые строки между блоками попадают в копирование, но не получают отдельного прямоугольника: у них нет visual line. Это осознанное упрощение; визуально диапазон остаётся непрерывным за счёт соседних строк.

Альтернативы:

- Считать высоту из `line_height` роли — тогда высота различается у заголовков, тела и таблиц, что противоречит требованию единой высоты.
- Объединять прямоугольники в один путь — усложняет скругление и клиппинг, не даёт выигрыша.

### 6. Курсор

`mouse_interaction` текстовых виджетов возвращает:

- `Pointer` над ссылкой (как сейчас);
- `Text` только если курсор внутри visual line или его левого поля;
- `None` иначе.

`SelectionSurface` возвращает `Text` только над левым полем строки, `None` в промежутках. `stack` выбирает первый ненулевой ответ сверху вниз; если ни один виджет не ответил, iced показывает обычную стрелку. Так I-beam не появляется над паддингом, промежутками, изображениями и линиями.

### 7. Копирование

На отпускании `DocumentSelection::finish()`:

1. Для `Line`-режима берёт `SourceIndex::range(anchor.line, focus.line)`.
2. Для `Text`-режима переводит обе позиции в исходные строки через `BlockSource::line_at` и берёт `SourceIndex::range(start_line, end_line)`.
3. Возвращает точный срез исходника от начала первой строки до конца последней, включая перевод строки последней строки, если он есть.

Так автоматически сохраняются `#`, `**`, `|`, отступы, пустые строки и не-текстовые элементы между блоками. Символьное выделение внутри одной строки расширяется до всей строки; выделение в коде даёт строки кода без ограждения, потому что `BlockSource` code-блока начинается с содержимого, а не с ```.

`Message::Selected(Option<String>)` и `Message::CopySelection` остаются прежними: app хранит готовый markdown-текст и пишет его по Ctrl+C. Пустое выделение публикует `None`.

### 8. Интеграция с виджетами

`ViewerText::selectable_from`/`flow_text` получают `BlockSource` и `Rc<DocumentSelection>`; `SelectableText` и `InlineFlow` получают те же данные билдерами. Оба виджета:

- регистрируют `BlockGeometry` в `layout()`;
- на нажатие вызывают `DocumentSelection::begin_text(...)`;
- на движение при активном drag вызывают `extend_to(content_point)`;
- на отпускание вызывают `finish()` и публикуют `Selected`;
- в `draw()` рисуют локальную часть общего диапазона;
- в `mouse_interaction` учитывают реальные visual lines.

`Viewer` остаётся хранилищем highlighter/шрифтов/анимаций. Новый адаптер `DocumentView<'_>` реализует `markdown::Viewer` на один вызов `view()`: он берёт `&Viewer`, `&SourceIndex`, `&DocumentSelection` и в `heading/paragraph/code_block` строит `BlockSource` из `Text::source_segments()`/`lines[i].source()`. Вложенные списки, цитаты и таблицы идут через дефолтные методы `Viewer`, поэтому каждый вложенный `Text` автоматически получает свою карту источника и позицию в документе.

### 9. Конфиг

`Selection` получает `radius: f32`, `height: f32`, `headings: HeadingHeights` и `code_height: f32`; `HeadingHeights` хранит шесть высот H1–H6. Парсинг — через `number_child`, отсутствие — дефолты `3.0`, `22.0`, `44/39/33/28/22/22`, `17.0`. `color` и `decoration` не меняются. `README.md` и `config.example.kdl` дополняются секцией:

```kdl
selection {
    color "selection"
    radius 3
    height 22
    headings { h1 44; h2 39; h3 33; h4 28; h5 22; h6 22 }
    code-height 17
    decoration { underline-offset 0.08; strikethrough-offset 0.5 }
}
```

### 10. Сброс и live reload

`Program` хранит `DocumentSelection` и `DocumentGeometry` рядом с `SelectionState`; при `open`/`reload` очищает оба и увеличивает generation. `Article` хранит `Arc<str>` исходника и `SourceIndex`; после перезагрузки создаётся новый `Article`, поэтому старые `BlockSource` не переиспользуются. `CopySelection` после перезагрузки без выделения ничего не пишет.

### 11. Скролл и мышь без пересборки документа

`WheelScroll` владеет `Scroll` и на кадрах `RedrawRequested` сам вычисляет новое смещение, пишет его в состояние дочернего `scrollable` и в общий `Rc<Cell<f32>>`. Сообщения `Wheeled`, `ScrollFrame` и `Scrolled` не публикуются: кадр анимации не проходит через `Program::update` и не вызывает `view()`.

`scrollable` не передаёт `RedrawRequested` содержимому, поэтому кадр скролла не обходит markdown-виджеты. `Column`/`Row` в `mouse_interaction` проверяют границы ребёнка, а `CursorMoved` передают только детям, пересекающим видимый viewport. Виджеты вне окна не участвуют в hover и курсоре, но layout и draw по-прежнему отсекаются по `viewport`.

`SelectionSurface` при активном drag перехватывает `CursorMoved` до содержимого, поэтому протяжка не обходит блоки и не публикует сообщения на каждое движение; уведомление о готовом тексте уходит только на отпускании.

## Risks / Trade-offs

- **Патч `vendor/iced_widget` меняет публичные типы `Text`/`Span`** → добавить поля с приватным доступом и методы, обновить все конструкторы внутри `markdown.rs`; существующий код сопоставляет варианты с `..`, поэтому поля не ломают вызовы.
- **Реестр геометрии дублирует glyph-позиции** → обновляется только в `layout`, а не на кадр; хранит минимальные `Glyph { x, width, start, end }`; для больших документов память растёт линейно по числу глифов, но это тот же порядок, что и cosmic buffer.
- **Ленивые/виртуализированные строки таблиц могут отсутствовать в реестре** → iced `table` раскладывает строки целиком; если появится виртуализация, hit-testing будет клампиться к ближайшей известной строке, а выделение не потеряет уже выбранные блоки.
- **Фиксированная высота подсветки может не совпадать с line box крупного заголовка** → это требование спецификации; прямоугольник центрируется по visual line, а значение настраивается.
- **Пустые строки не подсвечиваются** → попадают в копирование; визуальный разрыв допустим и зафиксирован в спеке.
- **Координаты окна и контента расходятся при прокрутке** → `SelectionSurface` переводит окно → контент через `scrollable_origin + offset`; виджеты получают уже сдвинутый курсор от `scrollable`; покрыть визуальным тестом с прокруткой и активным drag.
- **Построчный режим из паддинга окна забирает нажатия у декоративных зон** → surface перехватывает только точки, где в реестре есть строка и x левее её текста; остальные события уходят дальше.
- **Источник для inline-разметки может расходиться с видимым текстом при entities/экранировании** → `BlockSource` берёт ближайший байт источника и расширяет до целой строки; копирование всё равно возвращает исходную строку без потерь.

## Migration Plan

1. Пропатчить `vendor/iced_widget` диапазонами источника, не меняя поведение рендера; прогнать существующие тесты.
2. Добавить `SourceIndex` и `BlockSource` с тестами границ (CRLF, пустой файл, code lines, soft breaks).
3. Добавить `DocumentSelection`, `DocumentGeometry`, `SelectionSurface`; покрыть hit-testing, режимы и порядок тестами.
4. Перевести `SelectableText` на общий диапазон и реестр; удалить локальные selection/drag из `TextState`.
5. Перевести `InlineFlow`; удалить локальные selection/drag из `InlineState`.
6. Собрать `DocumentView`-адаптер и передать `BlockSource` из `Text::source_segments()`/code lines.
7. Подключить `SelectionSurface` в `view()` через `stack`, передать offset прокрутки; настроить курсор.
8. Добавить конфиг `radius/height/code-height`, обновить `README.md`, `config.example.kdl`, тесты парсинга.
9. Визуальная приёмка: кросс-блочное выделение, левое поле, код-блок, таблица, ресайз, прокрутка, Ctrl+C.

Откат: вернуть локальное выделение в `TextState`/`InlineState`, убрать adapter/surface/geometry, удалить поля источника из вендоренного markdown; конфиг-поля остаются безвредными дефолтами.

## Open Questions

Нет. Приняты и зафиксированы допущения: копирование включает перевод строки последней выбранной строки; пустые строки копируются, но не подсвечиваются; левое поле — это `window.padding` плюс отступ блока; высота подсветки задаётся в px и центрируется по visual line.
