## Context

Сейчас каждый markdown-блок текста — один виджет `SelectableText`, который держит один `iced_graphics::text::Paragraph` (cosmic-text buffer) на весь блок. Inline-код в нём — обычный `Span` с полем `highlight` и `padding`. `Span.padding` в iced 0.14 документирован как влияющий только на границы `Highlight`, поэтому он не участвует в раскладке. Фон рисуется по `Paragraph::span_bounds`, который прибивает прямоугольник к `line_top`, а высоту берёт из `glyph.line_height_opt`; для спана 13/1.3 внутри абзаца 17/1.3 это даёт 16.9 px вместо 22.1 px и асимметричные отступы. cosmic-text считает высоту визуальной строки по максимальному **явно заданному** `line_height` спанов, поэтому строка с inline-кодом схлопывается.

`iced 0.14` не передаёт `letter_spacing` из `Span` в cosmic `Attrs`, хотя cosmic-text его поддерживает. Значит, настройка letter-spacing требует изменения зависимости.

См. `proposal.md` — Why; `specs/configuration`, `specs/markdown-viewer`, `specs/text-selection` — требования.

## Goals / Non-Goals

**Goals:**

- Inline-код — отдельный атомарный inline-элемент с собственным box model, шрифтом и baseline.
- Сохранение исходных пробелов вокруг чипа; расстояние до соседних слов равно ширине этих пробелов.
- Корректный перенос строк с учётом полной ширины чипа и перестройка при ресайзе.
- Выделение и копирование через чип без изменения исходного текста.
- Настраиваемый `letter-spacing` в роли текста.
- Сохранить текущий layout для блоков без inline-кода.

**Non-Goals:**

- Выделение между разными блоками.
- Полная поддержка bidi/CJK line breaking в блоках с inline-кодом сверх текущего поведения.
- Per-snippet шрифты из markdown: шрифт задаётся ролью inline-code.
- Изменение код-блоков, картинок, ссылок и табличной сетки.
- Апгрейд iced до другой мажорной версии.

## Decisions

### 1. Inline-flow только для блоков с inline-кодом

`ViewerText` проверяет styled spans на наличие `highlight`. Если inline-кода нет, блок по-прежнему рендерится через `SelectableText` и старый cosmic-параграф. Если есть — блок рендерится новым `InlineFlow`-виджетом.

Альтернативы:

- Заменить `SelectableText` везде — больше blast radius и риск сломать блоки без кода.
- Оставить span + расширение пробелов — не даёт отдельного зазора у пунктуации, атомарности и точного сохранения числа пробелов.

### 2. Модель атомов

Стилизованные spans разбиваются на последовательность атомов:

- `Text` — непрерывный кусок spans без пробелов; шейпится как одна rich-text строка (`Wrapping::None`), хранит `Paragraph`, ширину, baseline и вертикальные метрики.
- `Space` — run пробелов; сохраняет количество символов исходника, является точкой переноса, не рисуется.
- `Chip` — inline-код; содержит свой `Paragraph` (`Wrapping::None`) с код-ролью, `padding`, `background`, `radius`.

Логический текст блока — конкатенация текстов исходных styled spans. Каждый атом хранит диапазон байтов в этом тексте. Пробелы вокруг `Chip` не схлопываются: каждый run сохраняется как `Space` с шириной, равной числу пробелов. Пустой `Space` не создаётся.

Отдельный атом создаётся только на границе пробела или inline-кода; соседние spans без пробелов группируются, чтобы сохранить kerning/ligatures внутри слова.

### 3. Измерение и кэш

- `Text` измеряется один раз на (набор spans, роль, конфиг) и кэшируется. Ширина и baseline не зависят от ширины строки.
- `Chip` измеряется код-ролью; ширина содержания включает letter-spacing. Внешняя ширина = `content + padding.left + padding.right`; пробелы вокруг задаются отдельными `Space`-атомами.
- `InlineFlow` кэширует атомы и их измерения; при ресайзе меняется только разбиение на строки и вертикальные позиции, повторного shaping нет.
- Атом шире доступной строки обрабатывается как многострочный: первый visual line становится строкой, остаток — продолжением на следующей. Это сохраняет поведение переноса длинных слов без отдельного движка.

### 4. Переносы и baseline

- Жадный перенос слева направо по измеренным ширинам. `Space` — точка разрыва; `Chip` атомарен: если не влезает в остаток, переносится целиком.
- Пробелы на конце строки не рисуются; на следующей строке чип начинается без ведущих пробелов.
- Для каждого атома известны `ascent`/`descent` относительно его baseline и высота box. Строка: `baseline = top + max_ascent`, `height = max_ascent + max_descent`. Вертикальный padding чипа входит в его ascent/descent, поэтому строка растёт и фон не перекрывает соседние строки.
- `Text` рисуется со сдвигом `baseline - atom_baseline`; `Chip` — фон и текст на той же baseline.

### 5. Рендер чипа

Фон — `fill_quad` с радиусом из конфига. Содержимое — `Paragraph` код-роли, letter-spacing включён. Padding — внутри фона; исходные пробелы — снаружи отдельными `Space`-атомами. Selection рисуется над фоном чипа и под текстом. Underline/strikethrough/link остаются на спанах `Text`.

### 6. Выделение и копирование

`InlineFlow` хранит selection как диапазон логических байтов, а не как позиции глифов. Hit-testing:

- найти строку по `y`, затем атом по `x`;
- для `Text` — `Paragraph::hit`/grapheme position, перевести в логический байт;
- для `Chip` — позиция внутри текста кода;
- для пробела/зазора — ближайшая граница.

Подсветка рисуется пересечением диапазона с каждым атомом. Копирование — срез логического текста, поэтому исходные пробелы сохраняются. При ресайзе диапазон остаётся прежним, пересчитываются только координаты. Generation-механизм очистки выделения переиспользуется из `SelectableText`.

### 7. Letter-spacing через локальный патч iced

Добавить `Span.letter_spacing: Option<f32>` (px), builder и `to_static` в `iced_core`, прокинуть в `iced_graphics::text::paragraph::with_spans` в cosmic `Attrs::letter_spacing` (cosmic ждёт EM: `px / size`). Markdown/rich-text спаны получают `None`. Патч минимальный, версия iced 0.14 фиксируется; вендорится через `[patch.crates-io]` и локальные `vendor/iced_*`.

Альтернативы:

- Обновиться до iced, где есть поле — текущая версия его не содержит, апгрейд ломает внутренний API `Paragraph::buffer`/`span_bounds`.
- Разбивать текст на символы и расставлять вручную — ломает shaping, лигатуры и копирование.

### 8. Конфиг

- `Role.letter_spacing: f32` (px, default 0), парсинг `letter-spacing`; применяется к спанам роли.
- `InlineCode.radius: f32` (px, default 4).
- `InlineCode.padding` — дефолт 4 px со всех сторон; `InlineCode.radius` — дефолт 4 px.
- `letter-spacing` и остальные поля остаются частичными: отсутствующее берётся из дефолта, неизвестное игнорируется.

### 9. Интеграция

`ViewerText::selectable_text` заменяется на выбор: `SelectableText` для блоков без кода, `InlineFlow` для блоков с кодом. Заголовки, абзацы, пункты списков, цитаты и ячейки таблиц используют один и тот же выбор. Для `Length::Shrink` flow сообщает ширину по максимальной строке и высоту по сумме строк; при изменении `limits` пересчитывает переносы.

## Risks / Trade-offs

- **Атомарный shaping теряет kerning/ligatures на границах слов** → группировать непрерывные spans без пробелов; блоки без кода идут старым путём; ограничение зафиксировать в документации.
- **Два layout-пути расходятся по поведению** → общий слой стилизации, общий generation-selection, тесты на оба пути; flow включается только при наличии кода.
- **Bidi/CJK переносы в flow-блоках проще, чем в cosmic** → считать это известным ограничением; для блоков с кодом использовать атомы-слова, для блоков без кода оставить cosmic.
- **Патч iced усложняет обновление зависимости** → минимальный diff, фиксированная версия, вендоренный патч и тест letter-spacing; откат — удалить патч и поле.
- **Ресайз и active selection** → selection в логических байтах; тест на ресайз с активным выделением.
- **Ширина таблицы/Shrink** → flow обязан возвращать корректный `min_bounds`; тест с узкой ячейкой и переносом чипа.
- **Рост line-height из-за вертикального padding** → допускается спецификацией; тест на отсутствие перекрытия соседних строк.
- **Performance** → измерения атомов кэшируются; ресайз только переразбивает строки; рисование без лишних аллокаций на кадр.

## Migration Plan

1. Вендорить патч iced с `Span.letter_spacing`; прогнать существующие тесты, убедиться, что без настройки поведение не изменилось.
2. Добавить конфиг `letter-spacing`, `padding`, `radius`, дефолты и парсинг; применить letter-spacing к спанам в старом пути.
3. Реализовать атомизацию, измерение и кэш; покрыть тестами границы (нет кода, код вплотную к пунктуации, несколько пробелов).
4. Реализовать `InlineFlow`: переносы, baseline, ресайз, отрисовку чипов.
5. Перевести выбор виджета в `ViewerText`; selection/copy/hit-testing и generation.
6. Обновить README, `config.example.kdl`; визуальная приёмка на фикстуре с `ебаться \`рылом\` в ламинат`, пунктуацией, длинным чипом и ресайзом.

Откат: вернуть `ViewerText` на `SelectableText`, удалить flow-ветку; конфиг-поля остаются безвредными; откатить вендоренный iced-патч.
