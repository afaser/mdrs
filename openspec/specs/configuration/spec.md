# configuration Specification

## Purpose

Единый KDL-конфиг задаёт все видимые параметры просмотрщика — палитру и прозрачность, шрифты и типографику, оформление код-блока, скроллбары, анимацию прокрутки, выделение и подсветку синтаксиса — с дефолтами Catppuccin Mocha Green и возможностью добавлять новые секции без ломки существующих файлов.

## Requirements

### Requirement: Обнаружение конфига

Приложение ДОЛЖНО (MUST) искать конфиг в `$XDG_CONFIG_HOME/mdrs/config.kdl`, при отсутствии переменной — в `~/.config/mdrs/config.kdl`, а путь из переменной `MDRS_CONFIG` ДОЛЖЕН (MUST) иметь приоритет. Если файла нет, приложение ДОЛЖНО (MUST) работать с дефолтными значениями и не показывать ошибку.

#### Scenario: Конфиг в XDG-каталоге

- **WHEN** файл `$XDG_CONFIG_HOME/mdrs/config.kdl` существует
- **THEN** приложение применяет его значения

#### Scenario: Переменная окружения

- **WHEN** задан `MDRS_CONFIG=/tmp/custom.kdl` и файл существует
- **THEN** приложение применяет `/tmp/custom.kdl`, а не файл в XDG-каталоге

#### Scenario: Конфига нет

- **WHEN** ни `MDRS_CONFIG`, ни XDG-файл не существуют
- **THEN** приложение запускается с дефолтным видом без сообщения об ошибке

### Requirement: Частичный и расширяемый конфиг

Конфиг ДОЛЖЕН (MUST) допускать отсутствие любой секции, любого поля и любой вложенной ветки: отсутствующее значение берётся из дефолта, а не считается ошибкой. Неизвестные секции и поля ДОЛЖНЫ (MUST) игнорироваться, чтобы конфиг, написанный для более новой версии, не ломал текущую. Повторяющаяся секция или поле ДОЛЖНЫ (MUST) разрешаться в пользу последнего значения.

#### Scenario: Только один цвет

- **WHEN** конфиг содержит только `theme.palette.accent "#ff0000"`
- **THEN** меняется только акцент, остальные цвета и размеры остаются дефолтными

#### Scenario: Неизвестная ветка

- **WHEN** конфиг содержит секцию `theme.future-branch { enabled #true }`, которой нет в приложении
- **THEN** приложение запускается, известные значения применяются, неизвестная ветка не влияет на вид

#### Scenario: Глубокая вложенность

- **WHEN** конфиг задаёт `theme.code-block.header.copy.color "#ff0000"`
- **THEN** применяется цвет иконки копирования, остальные параметры шапки остаются дефолтными

### Requirement: Ошибки конфига

Синтаксическая ошибка KDL ДОЛЖНА (MUST) приводить к работе с дефолтным конфигом и записи причины в лог, а не к падению или блокировке окна. Ошибка типа или значения отдельного поля ДОЛЖНА (MUST) откатывать только это поле к дефолту.

#### Scenario: Битый KDL

- **WHEN** файл конфига содержит незакрытую фигурную скобку
- **THEN** приложение запускается с дефолтным видом, а в лог пишется ошибка разбора с позицией

#### Scenario: Неверный цвет

- **WHEN** `theme.palette.background` содержит `"not-a-color"`
- **THEN** фон остаётся дефолтным, остальные корректные поля применяются

### Requirement: Палитра и прозрачность

Палитра ДОЛЖНА (MUST) задавать цвета фона, текста, акцента, опасности, границы, поверхности, выделения и роли iced (`primary`, `success`, `warning`, `danger`). Цвета ДОЛЖНЫ (MUST) принимать `#rrggbb`, `#rrggbbaa` или имя другого цвета палитры. `background-opacity` ДОЛЖНА (MUST) управлять прозрачностью фона: значение меньше `1.0` делает окно прозрачным, значение `1.0` — непрозрачным.

#### Scenario: Дефолтная палитра

- **WHEN** конфиг не задаёт палитру
- **THEN** фон `#1e1e2e`, текст `#cdd6f4`, акцент `#a6e3a1`, опасность `#f38ba8`

#### Scenario: Полупрозрачный фон

- **WHEN** `background-opacity` равен `0.9`
- **THEN** фон окна полупрозрачный, а подложка окна не перекрывает его непрозрачным цветом

#### Scenario: Ссылка на цвет палитры

- **WHEN** роль текста задаёт цвет `"accent"`, а палитра переопределяет `accent`
- **THEN** роль использует переопределённый акцент

### Requirement: Шрифты и script-runs

Конфиг ДОЛЖЕН (MUST) задавать именованные шрифты с семейством, script-привязкой и файлами лиц regular, bold, italic и bold-italic. Каждая роль текста ДОЛЖНА (MUST) ссылаться на цепочку шрифтов; символы латиницы, кириллицы и общих знаков ДОЛЖНЫ (MUST) разделяться на run'ы и отрисовываться шрифтом, чей script соответствует символу, с сохранением ссылок, подчёркиваний и зачёркиваний. Если для run'а нет подходящего шрифта, ДОЛЖЕН (MUST) использоваться первый шрифт цепочки.

#### Scenario: Латиница и кириллица в одном абзаце

- **WHEN** абзац содержит `Hello, мир`, латинский шрифт — Source Serif 4, кириллический — Lora
- **THEN** `Hello, ` отрисован Source Serif 4, `мир` — Lora, а текст копируется без изменений

#### Scenario: Жирный и курсивный

- **WHEN** markdown содержит `**жирный**` и `*курсивный*` текст
- **THEN** используются соответствующие bold и italic лица выбранного шрифта

#### Scenario: Дефолтные шрифты без системы

- **WHEN** приложение запущено на машине без установленных Lora и Source Serif 4
- **THEN** текст отрисован встроенными Lora и Source Serif 4

### Requirement: Лигатуры кода

Код ДОЛЖЕН (MUST) отрисовываться с включёнными лигатурами, если у шрифта кода есть соответствующая возможность. Конфиг ДОЛЖЕН (MUST) позволять включать и выключать лигатуры для роли кода.

#### Scenario: Лигатура стрелки

- **WHEN** блок кода содержит `->`, а у шрифта кода включены лигатуры
- **THEN** последовательность отрисована лигатурой, а не двумя отдельными глифами

#### Scenario: Лигатуры выключены

- **WHEN** роль кода задаёт `ligatures #false`
- **THEN** символы отрисовываются раздельно

### Requirement: Роли типографики

Конфиг ДОЛЖЕН (MUST) задавать для каждой видимой роли текста — body, H1–H6, inline-code, code, message и link — шрифтовую цепочку, размер, вес, line-height, letter-spacing и цвет. Заголовки ДОЛЖНЫ (MUST) настраиваться по уровням отдельно. Изменение роли НЕ ДОЛЖНО (MUST NOT) менять другие роли.

#### Scenario: Размер тела

- **WHEN** `theme.text.body.size` равен `20`
- **THEN** абзацы отрисованы размером 20, а размеры H1–H6 остаются дефолтными

#### Scenario: Цвет заголовка

- **WHEN** `theme.text.heading.color` равен `"#ff0000"`
- **THEN** все уровни заголовков используют этот цвет, а тело остаётся дефолтным

#### Scenario: Inline-код

- **WHEN** роль inline-code задаёт фон и цвет
- **THEN** inline-код в абзаце использует эти фон и цвет, не затрагивая обычный текст

#### Scenario: Letter-spacing роли

- **WHEN** `theme.text.inline-code.letter-spacing` равен `0.5`
- **THEN** расстояние между глифами внутри inline-кода увеличено на 0.5 px, а обычный текст не меняется

### Requirement: Оформление inline-кода

Inline-код ДОЛЖЕН (MUST) иметь настраиваемые фон, `padding` и радиус скругления. `padding` задаёт расстояние от текста кода до границы фона. Пробелы исходного markdown вокруг inline-кода ДОЛЖНЫ (MUST) сохраняться: они стоят снаружи границы чипа, и расстояние от границы до соседнего слова равно ширине этих пробелов. При отсутствии значений ДОЛЖНЫ (MUST) применяться дефолты: `padding` 4 px со всех сторон и радиус 4 px.

#### Scenario: Расстояние по исходным пробелам

- **WHEN** документ содержит ``ебаться `рылом` в ламинат``
- **THEN** между границей чипа и `ебаться`, а также между границей чипа и `в` стоит ровно один пробел исходного markdown; внутри границы вокруг `рылом` виден `padding` 4 px

#### Scenario: Несколько пробелов

- **WHEN** документ содержит ``а   `код`   б``
- **THEN** слева и справа от границы чипа сохранены все три пробела, а не один

#### Scenario: Скругление фона

- **WHEN** inline-code задаёт `radius 4`
- **THEN** углы фона inline-кода скруглены радиусом 4 px

#### Scenario: Дефолтные отступы

- **WHEN** конфиг не переопределяет `padding` и `radius` inline-кода
- **THEN** применяются 4 px padding со всех сторон и 4 px радиуса

#### Scenario: Фон и padding

- **WHEN** inline-code задаёт непрозрачный фон `"#313244"` и `padding 4`
- **THEN** фон окружает текст кода с отступом 4 px и не перекрывает соседний текст

### Requirement: Оформление код-блока

Код-блок ДОЛЖЕН (MUST) отображаться в рамке с настраиваемыми фоном, цветом, толщиной и радиусом границы. Шапка код-блока ДОЛЖНА (MUST) показывать язык блока и prompt-символ, если она включена, и ДОЛЖНА (MUST) содержать кнопку копирования всего кода. Фон, отступы, цвета, шрифт и размер шапки, а также видимость шапки ДОЛЖНЫ (MUST) задаваться конфигом. Для блока без языка ДОЛЖЕН (MUST) использоваться настраиваемый текст-заменитель.

#### Scenario: Шапка с языком

- **WHEN** документ содержит блок кода с языком `bash` и шапка включена
- **THEN** над кодом видны prompt-символ и «Bash», а справа — иконка копирования

#### Scenario: Копирование

- **WHEN** пользователь нажимает иконку копирования
- **THEN** системный буфер содержит весь код блока без подсветки и без шапки

#### Scenario: Шапка выключена

- **WHEN** `theme.code-block.header.show` равен `#false`
- **THEN** блок отображается без шапки, но код остаётся видимым и выделяемым

### Requirement: Скроллбары

Цвета дорожки и ползунка, ширины, отступы и расстояние между ползунком и дорожкой ДОЛЖНЫ (MUST) задаваться отдельно для вертикальной полосы документа и горизонтальной полосы код-блока.

#### Scenario: Цвет ползунка

- **WHEN** `theme.scrollbars.document.thumb` равен `"#ff0000"`
- **THEN** ползунок вертикальной полосы красный, а ползунок код-блока остаётся дефолтным

### Requirement: Анимация прокрутки

Сглаживание колеса ДОЛЖНО (MUST) настраиваться: время сглаживания, порог остановки, число строк и пикселей на щелчок, высота строки для расчёта шага и внешнее расстояние. Изменение этих значений НЕ ДОЛЖНО (MUST NOT) ломать границы документа и серию щелчков.

#### Scenario: Другой шаг колеса

- **WHEN** `theme.motion.wheel.lines-per-notch` равен `4`
- **THEN** один дискретный щелчок сдвигает документ на четыре строки

#### Scenario: Другое сглаживание

- **WHEN** `smoothing` равен `0.0`
- **THEN** позиция меняется без плавного переходного хвоста, но остаётся в границах документа

### Requirement: Выделение и подсветка

Цвет, радиус скругления и высота подсветки выделения, а также смещения линий подчёркивания и зачёркивания ДОЛЖНЫ (MUST) задаваться конфигом в `theme.selection`. Высота ДОЛЖНА (MUST) применяться ко всем не-кодовым блокам единообразно; для каждого уровня заголовка ДОЛЖНА (MUST) использоваться своя высота `theme.selection.headings.h1`…`h6`, а для строк многострочного fenced-блока кода — `code-height`. Тема подсветки синтаксиса ДОЛЖНА (MUST) выбираться встроенным именем или файлом `.tmTheme`, а цвета классов токенов (keyword, string, comment, number, function, type, operator, punctuation) ДОЛЖНЫ (MUST) переопределяться поверх темы.

Отсутствующие поля ДОЛЖНЫ (MUST) брать дефолты: `color "selection"`, `radius 3`, `height 22`, `headings.h1 44`, `headings.h2 39`, `headings.h3 33`, `headings.h4 28`, `headings.h5 22`, `headings.h6 22`, `code-height 17`, `underline-offset 0.08`, `strikethrough-offset 0.5`. Неизвестные поля и секции ДОЛЖНЫ (MUST) игнорироваться.

#### Scenario: Цвет выделения

- **WHEN** `theme.selection.color` равен `"#ff0000"`
- **THEN** выделенный мышью текст подсвечен красным во всех блоках документа

#### Scenario: Скругление выделения

- **WHEN** `theme.selection.radius` равен `6`
- **THEN** углы каждого прямоугольника подсветки скруглены радиусом 6 px

#### Scenario: Высота выделения

- **WHEN** `theme.selection.height` равен `28`
- **THEN** подсветка обычного текста, заголовков, списков, цитат и таблиц имеет высоту 28 px

#### Scenario: Высота заголовка

- **WHEN** `theme.selection.headings.h1` равен `46`, а `theme.selection.headings.h2` равен `40`
- **THEN** подсветка заголовка H1 имеет высоту 46 px, H2 — 40 px, а остальные не-кодовые блоки продолжают использовать `height`

#### Scenario: Высота строки кода

- **WHEN** `theme.selection.code-height` равен `20`
- **THEN** подсветка строк многострочного fenced-блока кода имеет высоту 20 px, а остальные блоки продолжают использовать `height`

#### Scenario: Дефолты секции

- **WHEN** конфиг не задаёт `theme.selection.radius`, `height`, `headings` и `code-height`
- **THEN** применяются радиус 3 px, высота 22 px, высоты заголовков 44/39/33/28/22/22 px и высота кода 17 px

#### Scenario: Переопределение токена

- **WHEN** `theme.highlighting.tokens.keyword` равен `"#ff0000"`
- **THEN** ключевые слова в код-блоках красные, остальные токены используют выбранную тему

#### Scenario: Файл темы

- **WHEN** `theme.highlighting.theme-file` указывает на существующий `.tmTheme`
- **THEN** подсветка использует цвета из файла, а отсутствующие классы берутся из дефолтной темы
