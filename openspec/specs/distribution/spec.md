# distribution Specification

## Purpose

Определяет упаковку `mdrs` как пакета Nix и доставку готового ELF через GitHub Releases: установку из флейк-ссылки без компиляции Rust, сборку из исходников, проверки CI, неизменяемый релиз и пин версии артефакта.

## Requirements

### Requirement: Пакет Nix

Флейк ДОЛЖЕН (MUST) предоставлять `packages.x86_64-linux.default`, `packages.x86_64-linux.mdrs` и `packages.x86_64-linux.source`. `default` и `mdrs` ДОЛЖНЫ (MUST) указывать на один пакет; при наличии `release.json` он ДОЛЖЕН (MUST) скачивать ELF по `url`, проверять его по `hash`, НЕ ДОЛЖЕН (MUST NOT) компилировать Rust и ставить `bin/mdrs`. `source` ДОЛЖЕН (MUST) собираться из `Cargo.lock`, прогонять тесты и ставить `bin/mdrs`; версия `source` — из `Cargo.toml`. Оба пакета ДОЛЖНЫ (MUST) использовать один набор runtime-библиотек и один список `runtimeDependencies`.

#### Scenario: Установка готового бинаря

- **WHEN** чистая машина с Nix и сетью выполняет `nix profile add github:afaser/mdrs` при наличии `release.json`
- **THEN** в логе установки есть скачивание ассета и `autoPatchelf`, нет вызовов `cargo` и `rustc`, `bin/mdrs` исполняется, а `default.version` совпадает с `release.json.version`

#### Scenario: Сборка из исходников

- **WHEN** выполняется `nix build .#source` в чистом клоне
- **THEN** тесты прогоняются, результат содержит `bin/mdrs`, `source.version` равен версии из `Cargo.toml`

#### Scenario: Первый релиз ещё не выпущен

- **WHEN** `release.json` отсутствует
- **THEN** `nix build .#default` собирает пакет из исходников, и установка не падает на отсутствующем ассете

#### Scenario: Версия после повышения в Cargo.toml

- **WHEN** в `Cargo.toml` уже `0.2.0`, а `release.json` ещё описывает `0.1.0`
- **THEN** `source.version` равен `0.2.0`, `default.version` равен `0.1.0`, и установка из `trunk` продолжает ставить прежний релиз без ошибки версии

#### Scenario: Обновление установки после релиза

- **WHEN** опубликован `vX.Y.Z`, пин-коммит попал в `trunk`, а пользователь выполняет `nix profile upgrade --refresh mdrs`
- **THEN** store path установленного пакета содержит `X.Y.Z`, и Rust не компилируется

### Requirement: Runtime-библиотеки в RPATH

Установленный ELF ДОЛЖЕН (MUST) содержать в RPATH каталоги библиотек, которые загружаются через `dlopen`: Vulkan loader, Wayland, xkbcommon, X11/xcb, курсоры/расширения X11 и D-Bus. Пользователь НЕ ДОЛЖЕН (MUST NOT) обязан задавать `LD_LIBRARY_PATH`. Vulkan ICD и драйвер GPU остаются системными; пакет НЕ ДОЛЖЕН (MUST NOT) подменять hardware adapter программным.

#### Scenario: RPATH установленного бинаря

- **WHEN** пакет `default` или `source` установлен
- **THEN** `patchelf --print-rpath $out/bin/mdrs` содержит каталоги `vulkan-loader` и `wayland`, а `auto-patchelf` не сообщает о недостающих зависимостях

#### Scenario: Системные библиотеки не нужны в LD_LIBRARY_PATH

- **WHEN** переменная `LD_LIBRARY_PATH` не задана, а GPU-драйвер и Vulkan ICD присутствуют в системе
- **THEN** ELF находит GUI-библиотеки из своего RPATH, а Vulkan adapter — из системного ICD

### Requirement: Переносимый вход флейка

Входы флейка НЕ ДОЛЖНЫ (MUST NOT) ссылаться на локальные пути файловой системы (`path:` или абсолютный `/nix/store/...`). `flake.lock` ДОЛЖЕН (MUST) фиксировать ревизию nixpkgs, доступную для скачивания с GitHub. `release.json` ДОЛЖЕН (MUST) содержать абсолютный HTTPS-URL ассета GitHub Release и его хеш в SRI. Оценка и сборка флейка ДОЛЖНЫ (MUST) работать на чистой машине без предварительно скачанного nixpkgs.

#### Scenario: Сборка на чистой машине

- **WHEN** чистая машина с Nix и сетью выполняет `nix build github:afaser/mdrs#default`
- **THEN** nixpkgs скачивается по зафиксированной в `flake.lock` ревизии, ассет — по URL из `release.json`, и пакет собирается без правки флейка

#### Scenario: Локальный путь в lock-файле

- **WHEN** `flake.lock` содержит вход с `"type": "path"`
- **THEN** CI ДОЛЖЕН падать на проверке флейка, а не пытаться собрать такой вход

### Requirement: CI на push и pull request

На каждый push в `trunk` и каждый pull request ДОЛЖЕН (MUST) запускаться workflow, который проверяет отсутствие `path`-входов, выполняет `nix flake check`, собирает `source` и `default` и проверяет RPATH установленного бинаря. Провал любой проверки ДОЛЖЕН (MUST) делать workflow неуспешным. Сборка pull request из форка НЕ ДОЛЖНА (MUST NOT) требовать секретов репозитория.

#### Scenario: Некомпилируемое изменение

- **WHEN** pull request содержит синтаксическую ошибку в `src/`
- **THEN** workflow завершается ошибкой на сборке `source`

#### Scenario: Корректное изменение

- **WHEN** pull request собирается, проходит `nix flake check`, а RPATH `result/bin/mdrs` содержит runtime-каталоги
- **THEN** workflow завершается успешно

#### Scenario: Pull request из форка

- **WHEN** pull request пришёл из форка без секретов репозитория
- **THEN** сборка и проверки выполняются без записи в GitHub и без падения из-за отсутствия секрета

#### Scenario: Битый пин релиза

- **WHEN** `release.json` содержит URL или хеш, по которому ассет не скачивается или не совпадает
- **THEN** сборка `default` в CI завершается ошибкой, а не ставит непроверенный архив

### Requirement: Неизменяемый релиз

Ручной release-workflow ДОЛЖЕН (MUST) принимать версию и запускаться на выбранной ветке. Он ДОЛЖЕН (MUST) отказывать, если версия не совпадает с `Cargo.toml`. При отсутствии опубликованного релиза `vX.Y.Z` workflow ДОЛЖЕН (MUST) собрать `source`, создать архив `mdrs-x86_64-linux.tar.gz` с ELF, вычислить SRI-хеш, проверить бинарный пакет из локального архива, записать `release.json`, создать коммит-пин и тег `vX.Y.Z`, создать draft-релиз с `--verify-tag`, загрузить ассет, опубликовать релиз, проверить скачивание по публичному URL и `nix build .#default` из пин-коммита, затем отправить пин в ветку запуска. Ассет и тег опубликованного релиза НЕ ДОЛЖНЫ (MUST NOT) перезаписываться или переноситься.

#### Scenario: Первый релиз версии

- **WHEN** release-workflow запущен на `trunk` с версией `0.1.0` при версии `0.1.0` в `Cargo.toml`
- **THEN** публикуется `v0.1.0` с архивом, тег `v0.1.0` указывает на коммит с `release.json`, `trunk` получает этот коммит, а установка из `trunk` и с тега ставит ELF без компиляции Rust

#### Scenario: Несовпадающая версия

- **WHEN** release-workflow запущен с версией `9.9.9` при версии `0.1.0` в `Cargo.toml`
- **THEN** workflow завершается ошибкой до сборки, релиз и тег не создаются

#### Scenario: Ошибка до публикации

- **WHEN** draft создан и ассет загружен, но публикация не удалась
- **THEN** draft и созданный этим запуском тег удаляются, пин-коммит не отправляется в ветку, прежний релиз продолжает работать

#### Scenario: Ошибка после публикации

- **WHEN** релиз опубликован, но отправка пин-коммита в ветку отклонена
- **THEN** релиз и тег остаются, ветка не меняется, а повторный запуск доводит только fast-forward отправку существующего пин-коммита

#### Scenario: Повторная попытка с изменённым исходником

- **WHEN** релиз `v0.1.0` уже опубликован, ветка ушла вперёд, и запуск снова требует `0.1.0`
- **THEN** workflow не пересобирает и не перезаписывает ассет, не переносит тег и завершается ошибкой, требуя новую версию

#### Scenario: Обновление nixpkgs

- **WHEN** ветка обновляет `flake.lock` и `Cargo.toml` до `0.1.1`, после чего release-workflow запускается с `0.1.1` на этой ветке
- **THEN** публикуется `v0.1.1` с бинарём, собранным из новых зависимостей, пин попадает в ветку, и `checks.default` проходит до слияния

#### Scenario: Одновременные запуски

- **WHEN** два release-workflow запущены одновременно
- **THEN** второй ждёт завершения первого и видит его опубликованный релиз или ошибку, но не загружает второй ассет с тем же именем
