# markdown-viewer Specification

## Purpose

Просмотрщик открывает markdown-документ с диска и показывает его в нативном окне с темой Catppuccin Mocha (зелёный акцент), встроенным шрифтом JetBrains Mono Nerd Font и обновлением при изменении файла без потери позиции чтения.

## Requirements

### Requirement: Открытие документа

Просмотрщик ДОЛЖЕН (MUST) открывать markdown-файл аргументом командной строки и диалогом выбора файла на любой поддерживаемой оконной системе, а перетаскиванием — там, где оконная система доставляет файлы в приложение (X11/XWayland).

#### Scenario: Аргумент командной строки

- **WHEN** процесс запущен как `mdrs path/to/file.md`
- **THEN** окно показывает содержимое этого файла, а заголовок окна содержит имя файла

#### Scenario: Выбор через диалог

- **WHEN** пользователь нажимает Ctrl+O и выбирает файл в системном диалоге
- **THEN** текущий документ заменяется выбранным

#### Scenario: Перетаскивание

- **WHEN** пользователь перетаскивает файл в окно приложения в сессии X11 или XWayland
- **THEN** приложение открывает этот файл

#### Scenario: Перетаскивание на Wayland

- **WHEN** приложение запущено в нативной сессии Wayland и пользователь перетаскивает файл
- **THEN** приложение не падает и не зависает; файл открывается через Ctrl+O или аргумент командной строки

### Requirement: Рендер markdown

Просмотрщик ДОЛЖЕН (MUST) отображать заголовки, абзацы, упорядоченные и неупорядоченные списки, цитаты, горизонтальные линии, таблицы, изображения, ссылки и блоки кода.

#### Scenario: Таблица

- **WHEN** документ содержит GFM-таблицу
- **THEN** она отображается сеткой с заголовком и строками

#### Scenario: Блок кода с языком

- **WHEN** документ содержит блок кода с указанным языком
- **THEN** токены подсвечиваются цветами темы, а не выводятся одним цветом

#### Scenario: Неизвестный язык

- **WHEN** у блока кода указан неизвестный язык
- **THEN** блок отображается моноширинным текстом без подсветки и без ошибки

#### Scenario: Относительное изображение

- **WHEN** документ ссылается на изображение относительным путём
- **THEN** изображение загружается из каталога документа

#### Scenario: Отсутствующее изображение

- **WHEN** файл изображения не найден
- **THEN** показывается alt-текст, приложение не завершается аварийно

### Requirement: Inline-код как атомарный чип

Inline-код ДОЛЖЕН (MUST) отображаться отдельным атомарным inline-элементом с собственным фоном, `padding`, радиусом и шрифтом роли inline-code. Чип ДОЛЖЕН (MUST) выравниваться по baseline строки и НЕ ДОЛЖЕН (MUST NOT) разрываться между визуальными строками. Пробелы исходного markdown вокруг inline-кода ДОЛЖНЫ (MUST) сохраняться и стоять снаружи границы чипа: расстояние от границы до соседнего слова равно ширине этих пробелов. Логический текст и копирование при этом ДОЛЖНЫ (MUST) сохранять исходные пробелы. Вертикальный `padding` чипа ДОЛЖЕН (MUST) учитываться в высоте строки, чтобы фон не перекрывал соседние строки. При изменении ширины окна переносы ДОЛЖНЫ (MUST) пересчитываться, чип остаётся целым и не выходит за границы текста.

#### Scenario: Расстояние до соседних слов

- **WHEN** документ содержит ``ебаться `рылом` в ламинат``
- **THEN** между границей чипа и `ебаться`, а также между границей чипа и `в` стоит ровно один пробел исходного markdown; внутри границы вокруг `рылом` виден `padding` 4 px

#### Scenario: Несколько пробелов

- **WHEN** документ содержит ``а   `код`   б``
- **THEN** все три пробела слева и справа сохранены, расстояние до соседних слов равно ширине трёх пробелов

#### Scenario: Код вплотную к пунктуации

- **WHEN** документ содержит `(`рылом`)` без пробелов вокруг inline-кода
- **THEN** граница чипа стоит вплотную к скобкам, а текст кода отделён от границы на `padding`

#### Scenario: Перенос строки

- **WHEN** чип целиком не помещается в остаток текущей строки
- **THEN** чип переносится на следующую строку целиком, без разрыва фона и текста кода

#### Scenario: Ресайз окна

- **WHEN** пользователь изменяет ширину окна, пока документ содержит inline-код
- **THEN** переносы пересчитываются по новой ширине, чипы остаются целыми, фон и текст не перекрывают соседние слова и строки

#### Scenario: Вертикальный padding

- **WHEN** inline-code задаёт `padding top 4` и `padding bottom 4`
- **THEN** высота строки с чипом увеличивается так, чтобы фон не перекрывал текст соседних строк

#### Scenario: Inline-код в разных блоках

- **WHEN** inline-код встречается в абзаце, заголовке, пункте списка, цитате или ячейке таблицы
- **THEN** во всех случаях он отображается атомарным чипом с одинаковыми правилами отступов и переносов

### Requirement: Полосы прокрутки не перекрывают содержимое

Полосы прокрутки документа и блока кода ДОЛЖНЫ (MUST) занимать отдельное место в раскладке, а не рисоваться поверх содержимого: вертикальная полоса документа не пересекает текст markdown, горизонтальная полоса блока кода не пересекает строки кода. Полосы ДОЛЖНЫ (MUST) оставаться видимыми и перетаскиваемыми, а колесо мыши и сохранение позиции прокрутки ДОЛЖНЫ (MUST) работать как раньше.

#### Scenario: Вертикальная полоса документа

- **WHEN** документ длиннее окна и пользователь прокручивает его до любой позиции
- **THEN** справа от текста видна вертикальная полоса, весь текст документа отрисован левее полосы и не перекрыт ею

#### Scenario: Горизонтальная полоса блока кода

- **WHEN** строки в блоке кода шире доступной ширины блока
- **THEN** горизонтальная полоса отображается под строками кода, нижняя строка кода не перекрыта полосой, а прокрутка полосой открывает правый край строк

### Requirement: Прокрутка колесом

Прокрутка колесом ДОЛЖНА (MUST) сдвигать документ не менее чем на восемь строк основного текста за один щелчок независимо от того, доставляет оконная система щелчок дискретной дельтой строк или пиксельной дельтой. Смещение ДОЛЖНО (MUST) происходить плавно: позиция меняется последовательными кадрами за время от 100 до 200 мс, а не одним мгновенным перескоком. Несколько щелчков подряд ДОЛЖНЫ (MUST) складываться без потери движения.

#### Scenario: Дискретный щелчок колеса

- **WHEN** пользователь делает один щелчок колеса, и оконная система сообщает одну дискретную строку
- **THEN** документ сдвигается на восемь строк основного текста

#### Scenario: Пиксельный щелчок колеса

- **WHEN** пользователь делает один щелчок колеса, и оконная система сообщает его пиксельной дельтой
- **THEN** документ сдвигается на восемь строк основного текста, а не на величину пиксельной дельты напрямую

#### Scenario: Плавный ход

- **WHEN** пользователь прокручивает документ колесом
- **THEN** между начальной и конечной позициями видны промежуточные позиции, переход завершается за 100–200 мс, рывка за один кадр нет

#### Scenario: Серия щелчков

- **WHEN** пользователь делает несколько щелчков колеса подряд до завершения предыдущей анимации
- **THEN** итоговое смещение равно сумме шагов всех щелчков, движение не теряется и не откатывается назад

#### Scenario: Границы документа

- **WHEN** документ прокручен до начала или до конца и пользователь крутит колесо в ту же сторону
- **THEN** позиция не выходит за границы содержимого, анимация завершается без бесконечного движения

#### Scenario: Полоса прокрутки и живое обновление

- **WHEN** пользователь перетаскивает ползунок полосы или файл документа обновляется на диске
- **THEN** перетаскивание работает как раньше, позиция после live reload восстанавливается, а незавершённая анимация колеса не мешает новой позиции

#### Scenario: Горизонтальная прокрутка блока кода

- **WHEN** пользователь прокручивает блок кода с широкими строками по горизонтали полосой или при зажатом Shift
- **THEN** блок кода прокручивается по горизонтали, а документ не получает лишнего вертикального смещения

### Requirement: Ссылки

Просмотрщик ДОЛЖЕН (MUST) открывать внешние ссылки в системном браузере, не заменяя документ внутри приложения.

#### Scenario: Внешняя ссылка

- **WHEN** пользователь кликает ссылку `https://...`
- **THEN** URL открывается системным браузером, окно просмотрщика продолжает показывать документ

### Requirement: Выделение и копирование

Текст документа ДОЛЖЕН (MUST) выделяться мышью и копироваться в системный буфер.

#### Scenario: Копирование фрагмента

- **WHEN** пользователь выделяет абзац и нажимает Ctrl+C
- **THEN** буфер обмена содержит выделенный текст

### Requirement: Тема

Приложение ДОЛЖНО (MUST) по умолчанию использовать палитру Catppuccin Mocha Green: фон `#1e1e2e`, основной текст `#cdd6f4`, зелёный акцент `#a6e3a1` для ссылок и заголовков. Палитра, прозрачность фона и цвета ролей ДОЛЖНЫ (MUST) переопределяться KDL-конфигом без пересборки, а при отсутствии конфига ДОЛЖНЫ (MUST) совпадать с перечисленными значениями.

#### Scenario: Акцентный цвет

- **WHEN** конфиг не задаёт палитру, а документ содержит заголовок первого уровня и ссылку
- **THEN** оба отрисованы цветом `#a6e3a1` на фоне `#1e1e2e`

#### Scenario: Акцент переопределён

- **WHEN** конфиг задаёт `theme.palette.accent "#ff0000"`
- **THEN** заголовки и ссылки отрисованы цветом `#ff0000`, а фон остаётся `#1e1e2e`

### Requirement: Шрифт

Приложение ДОЛЖНО (MUST) по умолчанию отображать латиницу шрифтом Source Serif 4, кириллицу — Lora, а код — JetBrains Mono Nerd Font размером 13 с лигатурами. Все дефолтные шрифты ДОЛЖНЫ (MUST) быть встроены в бинарь, чтобы приложение не зависело от установленных системных шрифтов. Гарнитуры, размеры, веса и лица bold/italic ДОЛЖНЫ (MUST) переопределяться конфигом.

#### Scenario: Машина без установленного шрифта

- **WHEN** приложение запущено на системе, где Source Serif 4, Lora и JetBrains Mono Nerd Font не установлены
- **THEN** документ отрисован встроенными шрифтами

#### Scenario: Кириллица в тексте

- **WHEN** документ содержит кириллический текст и конфиг не переопределяет шрифты
- **THEN** кириллица отрисована Lora, а латиница в том же абзаце — Source Serif 4

#### Scenario: Лигатуры кода

- **WHEN** блок кода содержит `->` и конфиг не выключает лигатуры
- **THEN** стрелка отрисована лигатурой

### Requirement: Код-блок с шапкой

Код-блок ДОЛЖЕН (MUST) отображаться в рамке с шапкой, если шапка включена: слева prompt-символ и язык блока, справа кнопка копирования всего кода. Нажатие кнопки ДОЛЖНО (MUST) помещать в системный буфер исходный код блока без подсветки и без шапки. Видимость шапки, её высота, фон, отступы, цвета, шрифт и размер, prompt-символ, текст для блока без языка и иконка копирования ДОЛЖНЫ (MUST) задаваться конфигом.

#### Scenario: Шапка с языком

- **WHEN** документ содержит блок кода с языком `bash`, а шапка включена
- **THEN** над кодом видны prompt-символ и «Bash», а справа — иконка копирования

#### Scenario: Копирование кода

- **WHEN** пользователь нажимает иконку копирования в шапке
- **THEN** системный буфер содержит весь код блока с сохранёнными пробелами и переводами строк

#### Scenario: Блок без языка

- **WHEN** документ содержит блок кода без указанного языка
- **THEN** в шапке показан настроенный текст-заменитель, а код остаётся подсвеченным как обычный текст

#### Scenario: Шапка выключена

- **WHEN** конфиг задаёт `theme.code-block.header.show #false`
- **THEN** рамка и код видны, шапка и кнопка копирования отсутствуют


### Requirement: Live reload

При изменении открытого файла приложение ДОЛЖНО (MUST) обновить содержимое в течение 500 мс, сохранив позицию прокрутки.

#### Scenario: Изменение файла в середине документа

- **WHEN** пользователь прокрутил документ и файл сохранён на диске
- **THEN** содержимое обновилось, а позиция прокрутки осталась прежней

#### Scenario: Файл временно отсутствует

- **WHEN** файл на мгновение исчез при атомарном сохранении
- **THEN** приложение сохраняет последнее содержимое и не показывает ошибку

### Requirement: Ошибки открытия

Приложение ДОЛЖНО (MUST) показывать сообщение об ошибке с путём и не завершаться аварийно, если файл не существует или недоступен для чтения.

#### Scenario: Несуществующий путь

- **WHEN** приложение запущено с путём, которого нет
- **THEN** окно показывает сообщение с этим путём

### Requirement: Время запуска

На референсной машине с тёплым кешем драйвера первый кадр ДОЛЖЕН (MUST) быть показан не позднее 150 мс с момента запуска процесса.

#### Scenario: Тёплый старт

- **WHEN** приложение запущено повторно с тем же документом
- **THEN** время от запуска процесса до первого кадра не превышает 150 мс

### Requirement: Аппаратный рендер

Приложение ДОЛЖНО (MUST) использовать аппаратный GPU-адаптер и не выбирать программный адаптер.

#### Scenario: Выбор адаптера

- **WHEN** приложение стартует на референсной машине с RADV и llvmpipe
- **THEN** используется RADV, программный адаптер не выбран

### Requirement: Без веб-рантайма

Приложение ДОЛЖНО (MUST) работать без JavaScript-движка, браузерного движка и сетевого доступа.

#### Scenario: Машина без Node и браузера

- **WHEN** приложение запущено в системе без Node.js и браузера
- **THEN** документ отрисован полностью
